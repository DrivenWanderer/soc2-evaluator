### Remediation Guidance for CFG-005: Permissive Cross-Origin Resource Sharing (CORS) Policy

**Category:** Configuration / Code
**Default TSC Criterion:** CC6.6 (Boundary Protection & Logical Access)

#### Immediate Actions:
1. **Remove Wildcard Origins with Credentials:** Never combine `AllowAnyOrigin()` with `AllowCredentials()`. Browsers reject this combination, but misconfigured headers can expose authenticated API resources to unauthorized third-party origins.
2. **Explicitly Specify Allowed Origins:** Enumerate trusted origin domains (e.g., your production frontend domain, staging frontend domain).
3. **Use Environment-Specific Policies:** Isolate `localhost` development origins to development environments only.

#### Code Example (ASP.NET Core):
```csharp
// BEFORE (Insecure - Wildcard origin):
builder.Services.AddCors(options =>
{
    options.AddDefaultPolicy(policy =>
    {
        policy.AllowAnyOrigin()
              .AllowAnyHeader()
              .AllowAnyMethod();
    });
});

// AFTER (Secure - Explicit origin whitelist):
builder.Services.AddCors(options =>
{
    options.AddDefaultPolicy(policy =>
    {
        policy.WithOrigins("https://app.yourcompany.com", "https://admin.yourcompany.com")
              .AllowAnyHeader()
              .AllowAnyMethod()
              .AllowCredentials();
    });
});
```
