### Remediation Guidance for SEC-001: Hardcoded Secrets

**Category:** Code / Configuration
**Default TSC Criterion:** CC6.1 (Logical Access Controls)

#### Immediate Actions:
1. **Revoke and Rotate:** Immediately consider the detected credential compromised. Revoke the token or rotate the database password in the upstream system.
2. **Remove Secret from Git History:** Removing the secret from the current commit is not enough; purge historical commits using `git-filter-repo` or BFG Repo-Cleaner if previously pushed.

#### Recommended Architecture:
Move credentials and connection strings out of source-controlled configuration files into managed identity or secret management systems:

- **Azure:** Use Azure Key Vault with Azure Managed Identities (`DefaultAzureCredential` from `Azure.Identity`).
- **AWS:** Use AWS Secrets Manager or Parameter Store with IAM Roles.
- **Local Development:** Use .NET Secret Manager (`dotnet user-secrets init` and `dotnet user-secrets set`).

#### Configuration Example (appsettings.json):
```json
// BEFORE (Insecure - Plaintext password in repository):
"ConnectionStrings": {
  "DefaultConnection": "Server=tcp:sqlserver.database.windows.net,1433;Database=prod_db;User ID=cloudadmin;Password=P@ssw0rd123456!;"
}

// AFTER (Secure - Managed Identity with no embedded password):
"ConnectionStrings": {
  "DefaultConnection": "Server=tcp:sqlserver.database.windows.net,1433;Database=prod_db;Authentication=Active Directory Default;Encrypt=True;"
}
```
