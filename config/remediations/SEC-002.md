### Remediation Guidance for SEC-002: Weak Cryptographic Algorithm

**Category:** Code
**Default TSC Criteria:** CC6.1, CC6.7 (Logical Access & Transmission Security)

#### Immediate Actions:
1. **Identify Usage Context:** Determine whether the hash or cipher is used for security purposes (passwords, tokens, digital signatures, data encryption) or non-security purposes (dictionary lookups, cache keys).
2. **Replace Legacy Algorithms:**
   - For hashing / integrity: Replace `MD5` or `SHA1` with `SHA256`, `SHA384`, or `SHA512` (`System.Security.Cryptography.SHA256.Create()`).
   - For password hashing: Use standard key-derivation functions such as `Argon2id`, `PBKDF2` (`Rfc2898DeriveBytes`), or `BCrypt`.
   - For symmetric encryption: Replace `DES`, `TripleDES`, or `RC4` with `AES-256-GCM` or `AES-256-CBC` (`Aes.Create()`).

#### Code Example (.NET C#):
```csharp
// BEFORE (Insecure - MD5 is cryptographically broken):
using var md5 = System.Security.Cryptography.MD5.Create();
var hash = md5.ComputeHash(data);

// AFTER (Secure - SHA256):
using var sha256 = System.Security.Cryptography.SHA256.Create();
var hash = sha256.ComputeHash(data);
```
