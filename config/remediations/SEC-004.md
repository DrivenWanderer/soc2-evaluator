### Remediation Guidance for SEC-004: Disabled TLS Certificate Validation

**Category:** Code
**Default TSC Criterion:** CC6.7 (Transmission Security & Encryption in Transit)

#### Immediate Actions:
1. **Remove Custom Validation Overrides:** Remove any callbacks such as `ServerCertificateCustomValidationCallback = (_, _, _, _) => true` or `ServerCertificateValidationCallback = delegate { return true; }`.
2. **Resolve Root Cause for Untrusted Certificates:**
   - In local development: Trust the local development certificate (`dotnet dev-certs https --trust`).
   - In corporate/internal networks: Install the internal enterprise root CA certificate into the machine/container trust store rather than bypassing validation in application code.
   - In third-party integrations: Ensure the external endpoint serves a valid certificate issued by a public trusted CA.

#### Code Example (.NET C#):
```csharp
// BEFORE (Insecure - Disables TLS validation entirely, enabling Man-in-the-Middle attacks):
var handler = new HttpClientHandler
{
    ServerCertificateCustomValidationCallback = (sender, cert, chain, sslPolicyErrors) => true
};
var client = new HttpClient(handler);

// AFTER (Secure - Default platform CA trust store validates server certificates):
var handler = new HttpClientHandler();
var client = new HttpClient(handler);
```
