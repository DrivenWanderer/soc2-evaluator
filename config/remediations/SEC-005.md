### Remediation Guidance for SEC-005: SQL Injection via String Concatenation

**Category:** Code
**Default TSC Criteria:** CC6.1, CC7.1 (Data Protection & Vulnerability Mitigation)

#### Immediate Actions:
1. **Identify Vulnerable Data Access Code:** Locate raw SQL strings constructed via `+`, string interpolation (`$"..."`), or `string.Format`.
2. **Switch to Parameterized Queries:** Always use parameterized SQL (`@param`) or Object-Relational Mappers (Entity Framework Core, Dapper) with strongly-typed parameter objects.
3. **Never Concatenate Untrusted Input:** Treat all user input, query parameters, route variables, and header values as untrusted.

#### Code Example (.NET C# / Dapper / EF Core):
```csharp
// BEFORE (Insecure - String concatenation allows SQL injection):
var query = "SELECT * FROM Users WHERE Email = '" + userEmail + "'";
using var cmd = new SqlCommand(query, conn);

// AFTER (Secure - Parameterized SQL query):
var query = "SELECT * FROM Users WHERE Email = @Email";
using var cmd = new SqlCommand(query, conn);
cmd.Parameters.AddWithValue("@Email", userEmail);

// Or using Dapper (Secure):
var user = await conn.QuerySingleOrDefaultAsync<User>(
    "SELECT * FROM Users WHERE Email = @Email",
    new { Email = userEmail });
```
